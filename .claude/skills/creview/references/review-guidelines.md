# 공통 코드 리뷰 기준

일반적인 코드 리뷰 판단을 사용한다. 변경으로 새로 생기거나 악화된 구체적인 결함·회귀와 명시적 저장소 규칙 위반을 우선한다. 보안·성능·설계 문제도 실제 발생 조건과 영향에 근거해 판단한다. 기존 문제, 단순 요약, 조치 불필요한 관찰, 스타일 취향은 발견 사항에 포함하지 않는다.

각 발견에는 실제 영향에 따라 심각도를 붙인다.

- **Critical**: 심각한 기능 장애·데이터 손실·보안 영향 등 머지를 막아야 하는 문제
- **Warning**: 수정이 필요한 버그·회귀·명시적 규칙 위반
- **Nit**: 사용자가 개선 제안까지 요청한 경우에만, 명확한 유지보수 이점이 있는 선택적 개선

심각도와 확신도를 구분한다. 핵심 전제가 미확인인 주장은 추가 확인하며, 확신이 부족하다는 이유로 Nit으로 낮추지 않는다. 확인할 수 없는 중요한 사항은 발견 사항과 분리해 검증 한계로 적는다. 측정하지 않은 성능 수치를 만들어 쓰지 않는다.

발견 사항은 심각도순으로 최종 답변 본문에 상세히 작성한다. 인라인 댓글·리뷰 카드는 보조 수단이며, 본문 설명을 대체하지 않는다.

각 항목에 최종 상태 기준의 정확한 `파일:라인`, 발생 조건, 원인, 실제 영향과 근거를 포함해, 댓글을 펼치지 않아도 이해하고 판단할 수 있게 설명한다. 삭제된 코드 위치는 삭제 전 기준임을 표시한다.

리포트는 한국어로 작성한다. 파일별 변경 설명이나 고정된 축별 보고는 요구하지 않는다.

발견 사항이 없으면 이를 명시한다. 수행하지 못한 중요한 검증이나 잔여 위험이 있을 때만 덧붙이고, 실행하지 않은 테스트를 통과했다고 보고하지 않는다.
