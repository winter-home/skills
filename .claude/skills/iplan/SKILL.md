# iplan — 플랜 단계별 구현

플랜의 단계를 순서대로 구현하고, 단계마다 lreview 루프를 통과하면 커밋한다. iplan 호출은 단계별 커밋과 단계 관련 검증(단위·타입·린트 등) 실행을 허락한 것으로 본다. 푸시와 브랜치 변경은 하지 않는다.

## 인자

- 첫 인자는 플랜 파일 경로다. 없거나 파일이 없으면 종료한다.
- 둘째 인자는 lreview 리뷰어 구성이며, lreview를 실행할 때마다 그대로 넘긴다. 없으면 lreview 기본값을 쓴다.

## 준비

1. 플랜 파일 외의 tracked 변경이 있으면 종료한다. 단계 경계를 커밋으로 나누므로 시작 전 변경이 섞이면 안 된다.
2. 실행 디렉터리를 만든다: `tmp/iplan/<yyyyMMdd-HHmmss>`. 단계 기록(`progress.md`)을 둔다.

## 단계 정리

- 보류를 뺀 미체크 항목이 남은 단계를 `선행`을 지키며 순서대로 고른다. 다시 실행하면 첫 미완료 단계부터 이어서 하고, 남은 단계가 없으면 마지막 단계의 「단계 실행」 1번을 수행한 뒤 「통과」 1번(전체 검증)부터 한다.
- 단계가 한 번의 구현·리뷰로 끝낼 수 있는 하나의 변경 묶음인지 판단한다. 크면 `### N-1.`, `### N-2.`처럼 세부 단계로 나누고, 원래 단계의 체크 항목을 세부 단계로 옮겨 완료 조건과 함께 플랜에 기록한다. 이미 완료된 기록은 바꾸지 않는다.
- 실기기·사용자 결정·외부 자료가 필요한 항목은 `- [ ] 보류:`로 표시하고 구현 대상에서 뺀다. 보류 항목에 의존하는 단계에 이르면 중단한다.

## 단계 실행

단계마다 아래를 순서대로 수행한다.

1. 시작 커밋(`git rev-parse HEAD`)과 untracked 파일 목록을 `progress.md`에 기록한다.
2. 플랜과 저장소 규칙에 따라 구현한다. 새 파일은 `git add -N`으로 리뷰 범위에 넣는다. 단계 관련 검증을 같은 원인으로 세 번 고쳐도 통과하지 못하거나 완료 조건을 충족할 수 없으면 구현 실패다. 환경 오류면 iplan을 중단한다.
3. `../lreview/SKILL.md`를 읽고 리뷰어 구성과 리뷰 집중 영역(플랜 경로·현재 단계)을 인자로, 1번의 untracked 목록을 기준 목록으로 넘겨 그 절차를 수행한다. brief에는 단계의 체크 항목·완료 조건, 검증 지시·허락 범위, 이후 단계로 미룬 범위를 쓴다.
   - 구현 실패면 lreview에 구현 실패로 「복구」를 요청한다.
   - 구현했는데 tracked 변경이 없으면 lreview 없이 통과로 처리한다.
   - lreview 실행 디렉터리를 `progress.md`에 기록한다.
4. lreview 결과로 판정한다.

| lreview 결과                                                               | 처리                  |
| -------------------------------------------------------------------------- | --------------------- |
| 수용할 지적 없음·유예만 남음, Nit 적용 후 종료, 복구의 모든 세부 단계 통과 | 통과                  |
| 리뷰어 실행 실패·복구 중단 등 lreview가 중단됨                             | iplan 중단(롤백 없음) |

### 통과

1. 마지막 단계면 전체 검증을 실행한다. 실패 원인별 수정 횟수를 `progress.md`에 누적하고 lreview 재호출·복구 후에도 유지한다. 같은 원인으로 세 번 고쳐도 실패하거나 환경 오류면 새 복구 없이 iplan을 중단한다. 그 전에는 고친 뒤 단계 실행 3번부터 다시 한다. brief에는 미커밋 작업 설명을 유지하며 전체 검증 실패 원인·수정 대상·완료 조건을 추가하고, 이미 커밋된 항목은 완료로 구분한다.
2. 플랜에서 단계의 체크 항목을 `[x]`로 바꾼다.
3. 단계에서 바꾼 tracked 파일만 stage하고 `../commit/SKILL.md`의 메시지 규칙으로 커밋한다. 복구가 이미 커밋해 변경이 없으면 건너뛴다.
4. 커밋 해시를 `progress.md`에 기록하고 다음 단계로 넘어간다. 복구를 거쳤으면 세부 단계 커밋도 기록한다.

## 최종 보고

- 완료·보류·중단한 단계와 단계별 커밋
- 나눈 단계와 그 이유(복구의 세부 단계 포함)
- 복구 patch 경로
- 수행하지 않은 검증
- 실행 디렉터리 경로
