# iplan — 플랜 단계별 구현

플랜의 단계를 순서대로 구현하고, 단계마다 lreview 루프를 통과하면 커밋한다. iplan 호출은 단계별 커밋과 단계 관련 검증(단위·타입·린트 등) 실행을 허락한 것으로 본다. 푸시와 브랜치 변경은 하지 않는다.

## 인자

- 첫 인자는 플랜 파일 경로다. 없거나 파일이 없으면 종료한다.
- 둘째 인자는 lreview 리뷰어 구성이며, lreview를 실행할 때마다 그대로 넘긴다. 없으면 lreview 기본값을 쓴다.

## 준비

1. tracked 변경이 있으면 종료한다. 단계 경계를 커밋으로 나누므로 시작 전 변경이 섞이면 안 된다.
2. 실행 디렉터리를 만든다: `tmp/iplan/<yyyyMMdd-HHmmss>`. 단계 기록(`progress.md`)과 롤백 patch를 둔다.

## 단계 정리

- 보류를 뺀 미체크 항목이 남은 단계를 `선행`을 지키며 순서대로 고른다. 다시 실행하면 첫 미완료 단계부터 이어서 한다.
- 단계가 한 번의 구현·리뷰로 끝낼 수 있는 하나의 변경 묶음인지 판단한다. 크면 `### N-1.`, `### N-2.`처럼 세부 단계로 나누고, 원래 단계의 체크 항목을 세부 단계로 옮겨 완료 조건과 함께 플랜에 기록한다. 이미 완료된 기록은 바꾸지 않는다.
- 실기기·사용자 결정·외부 자료가 필요한 항목은 `- [ ] 보류:`로 표시하고 구현 대상에서 뺀다. 보류 항목에 의존하는 단계에 이르면 중단한다.

## 단계 실행

단계마다 아래를 순서대로 수행한다.

1. 시작 커밋(`git rev-parse HEAD`)과 untracked 파일 목록을 `progress.md`에 기록한다.
2. 플랜과 저장소 규칙에 따라 구현한다. 새 파일은 `git add -N`으로 리뷰 범위에 넣는다. 단계 관련 검증을 같은 원인으로 세 번 고쳐도 통과하지 못하거나 완료 조건을 충족할 수 없으면 lreview 없이 실패로 처리한다. 환경 오류면 iplan을 중단한다.
3. tracked 변경이 없으면 lreview 없이 통과로 처리한다. 있으면 `../lreview/SKILL.md`를 읽고 리뷰어 구성과 리뷰 집중 영역(플랜 경로·현재 단계)을 인자로 그 절차를 수행한다. brief에는 단계의 체크 항목·완료 조건과 이후 단계로 미룬 범위도 쓴다.
4. lreview 결과로 판정한다.

| lreview 결과                                        | 처리                  |
| --------------------------------------------------- | --------------------- |
| 수용할 지적 없음·유예만 남음, 또는 Nit 적용 후 종료 | 통과                  |
| 마지막 라운드에 권장안이 남음                       | 실패                  |
| 리뷰어 실행 실패 등 lreview 자체가 중단됨           | iplan 중단(롤백 없음) |

### 통과

1. 마지막 단계면 전체 검증을 1회 실행한다. 실패하면 단계 실행 2번의 상한·환경 오류 규칙에 따라 고친 뒤 3번부터 다시 한다.
2. 플랜에서 단계의 체크 항목을 `[x]`로 바꾼다.
3. 단계에서 바꾼 tracked 파일만 stage하고 `../commit/SKILL.md`의 메시지 규칙으로 커밋한다. 변경이 없으면 건너뛴다.
4. 커밋 해시를 `progress.md`에 기록하고 다음 단계로 넘어간다.

### 실패(구현 미완료·lreview 최대 라운드 소진)

1. `git diff HEAD --binary`를 `step-<번호>-attempt-<회차>.patch`로 저장하고, 실행한 lreview 디렉터리가 있으면 함께 `progress.md`에 기록한다.
2. `git reset --hard <시작 커밋>`으로 되돌리고, 시작 목록에 없던 untracked 파일만 지운다.
3. 검증 결과·lreview 보고서·시도 patch로 실패 원인을 분석해 단계를 세부 단계로 나눠 플랜에 기록하고, 첫 세부 단계부터 다시 구현한다. patch는 문제없던 부분만 참고하고 통째로 다시 적용하지 않는다.
4. 원래 단계 기준으로 두 번 나눈 뒤에도 실패하면 중단한다.

## 최종 보고

- 수행하지 않은 검증
- 실행 디렉터리 경로
