# lreview — 리뷰·검증·개선 루프

`../rreview/SKILL.md`의 리뷰·검증을 라운드마다 반복하고 권장안을 적용한다. 수용할 지적이 없을 때까지 라운드를 반복한다.

## 인자·준비

rreview의 「인자」·「준비」를 따른다.

- 실행 디렉터리는 `tmp/lreview/<yyyyMMdd-HHmmss>`다.
- 리뷰어는 라운드마다 같은 구성으로 새로 띄운다.
- 요청 범위가 바뀌면 `brief.md`를 갱신한다.

## 라운드

최대 10라운드. 라운드 N마다 아래를 순서대로 수행한다.

### 1. 리뷰·검증

rreview의 「리뷰」를 수행한다. 결과 디렉터리는 `<실행 디렉터리>/round-N`이다.

- 실패한 리뷰어가 있는 라운드는 "수용할 지적 없음" 종료의 근거로 쓰지 않는다. 같은 구성으로 라운드를 다시 실행하며, 다시 실행한 라운드도 최대 라운드 수에 포함한다.
- 같은 리뷰어가 같은 원인으로 두 라운드 연속 실패하면 중단한다.
- 검증할 때 실행 디렉터리의 `ledger.md`(이전 라운드 기록)를 함께 본다. 이전에 기각한 지적이 다시 나오면 앞선 근거를 인용해 기각한다. 이전 라운드 수정이 만든 코드를 다시 지적하면 vreview의 「재설계 후 적용」 조건으로 판단한다.
- rreview 3·4의 정리와 보고서를 출력한 다음, vreview 보고서를 `round-N/vreview.md`에 저장하고 권장안을 적용한다. 파일 저장으로 출력을 대신하지 않는다.

### 2. 판정과 적용

| 조건                                                   | 처리                                      |
| ------------------------------------------------------ | ----------------------------------------- |
| 수용·일부 수용 항목이 없거나 권장 액션이 모두 「유예」 | 종료                                      |
| 수용 항목이 creview의 Nit뿐                            | 적용하고 종료(재리뷰하지 않음)            |
| 그 외, 마지막 라운드                                   | 적용하지 않고 종료, 남은 권장안을 보고    |
| 그 외                                                  | 종합 권장 액션대로 적용하고 다음 라운드로 |

- sreview 지적은 심각도가 없으므로 Nit으로 보지 않는다.
- 「통합 후 적용」이면 개별 패치 대신 그룹 수정 하나로 적용한다.
- 「재설계 후 적용」이면 현재 상태에서 제시한 경계대로 다시 설계해 구현한다.
- 적용할 때 변경 파일에 해당하는 저장소 규칙을 따른다. 빌드·테스트는 사용자가 이번 호출이나 대화에서 명시적으로 허락한 경우에만 한다. `git add -N` 외의 stage와 commit은 하지 않는다.
- `ledger.md`에 라운드 기록을 덧붙인다: 지적 요약(리뷰어, `파일:라인`), 판정, 적용 여부, 수정한 파일.

## 최종 보고

- 진행한 라운드 수와 종료 사유
- 라운드별 실행 리뷰어(실패 포함), 수용·기각 수, 적용한 수정
- 남은 항목: 보류·유예, 적용하지 않은 권장안, 재리뷰를 거치지 않은 마지막 수정
- 수행하지 않은 검증(빌드·테스트)
- 실행 디렉터리 경로
