# skcheck — 스킬 정합성 점검

사용자가 지정한 스킬 저장소·스킬 폴더와 그 소유 플러그인을 점검한다. 대상이 없으면 현재 프로젝트를 사용한다. 설치 캐시를 대상으로 대신 사용하지 않는다. 파일 수정·stage·커밋은 하지 않는다.

## 범위와 방법

- 지정한 스킬 폴더를 우선한다. 프로젝트를 지정하면 `skills/`, `.agents/skills/`, `.claude/skills/`를 함께 확인한다. 루트에 `SKILL.md`가 있으면 단일 스킬로 보고, 표준 폴더가 없으면 직계 하위의 스킬을 확인한다. 같은 실체를 가리키는 링크는 중복 검토하지 않는다.
- 파일 열람·검색 도구로 원문을 직접 읽고 비교한다. 전용 검사기나 별도 설정 파일은 사용하지 않는다. 플러그인 매니페스트·README·Git 저장소는 필수가 아니다.
- 단일 스킬도 배포 경로·설정을 근거로 소유 플러그인을 확인하며, 상위 매니페스트만으로 소속을 단정하지 않는다. 마켓플레이스는 소유자에서 가장 가까운 상위 카탈로그의 해당 등록 항목만 비교하며 다른 플러그인의 경로는 따라가지 않는다.

## 점검 기준

- 참조: 파일·링크·앵커·「절」의 대상과 내용을 확인한다. 연결된 문서도 읽고 인자·기본값·책임·종료 조건의 충돌을 살핀다. 용어 강조와 절 참조, 실행 경로·생성 파일과 문서 상대 경로를 구별한다. 기준이 모호하거나 해석할 수 없으면 추측으로 통과시키지 않는다.
- 호출 설정: 경로·매니페스트·메타데이터에서 지원 호스트를 확인하고 Claude의 `disable-model-invocation`과 Codex의 `policy.allow_implicit_invocation`을 비교한다. 저장소 문서나 사용자 요청에서 같은 정책을 기대하는 짝을 확인한 경우 함께 검토한다. 이름만으로 짝을 단정하거나 단일 호스트용 스킬에 다른 호스트의 설정을 요구하지 않는다. 차이는 의도 확인이 필요한 경고다.
- 목록·등록: 스킬 이름과 디렉터리명, 소유 플러그인의 매니페스트 간 이름·버전, 해당 카탈로그 등록 정보를 비교한다. README는 설명하는 범위에 맞춰 확인하고 일부 소개를 전체 목록으로 간주하지 않는다.

## 보고

- 오류·경고별 `파일:라인`, 실제 불일치, 영향과 최소 수정안을 적는다. 의도된 차이는 근거와 함께 구분한다.
- 검토한 스킬·관련 문서와 확인하지 못한 항목을 밝힌다. 부분 검토에서는 범위 밖 스킬을 누락으로 보고하지 않고 생략한 전역 비교를 명시한다. 문제가 없으면 검토 범위 내 발견 없음으로 보고한다.
