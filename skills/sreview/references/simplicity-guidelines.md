# 변경 범위·간결성 리뷰 기준

요청을 충족하는 데 불필요한 코드와 테스트가 추가됐는지 판단한다. 구현 자체를 요구사항의 근거로 삼지 않으며, 목표가 불명확하면 범위 위반을 단정하지 않는다.

## 검토 기준

- **범위:** 요청과 무관한 기능·옵션·공개 API·리팩토링이 추가됐는가?
- **기존 경로 활용:** 기존 함수·처리 경로로 충분한데 새 상태·분기·우회 경로를 만들었거나, 같은 책임·판단이 중복됐는가?
- **구조의 필요성:** 새 추상화·검증·fallback이 실제 호출 경로와 요구사항에 필요한가?
- **테스트:** 기존 테스트가 놓치는 새 동작만 최소로 검증하는가? 세부 기준은 `AGENTS.md` 또는 `AGENTS.override.md`를 따른다.

## 판단과 보고

- 줄 수가 많거나 호출부가 하나라는 이유만으로 제거를 권하지 않는다. 파일 분리나 helper 추출만으로 복잡도가 줄었다고 판단하지 않는다.
- 요청과 호출부가 요구하는 동작·오류 처리·취소·자원 수명·정합성과 테스트의 검증 강도를 유지하는 대안만 권한다(예: 성공 검증을 호출 확인으로 바꾸지 않는다).
- 확인된 항목만 한국어로, 최종 상태 기준 `파일:라인 → 불필요한 이유와 근거 → 더 작은 대안 → 유지할 계약`으로 간결하게 보고한다. 같은 원인은 묶고, 변경과 무관한 기존 문제·스타일 취향·추측성 개선은 제외한다.
- 근거가 부족한 중요한 사항은 확인 필요 항목으로 분리한다. 지적할 내용이 없으면 명시하며, 항목 수를 채우거나 간결성을 점수화하지 않는다.
