# vreview — 코드리뷰 결과 검토 및 개선 제안

전달받은 코드리뷰 결과의 타당성을 검토하고, 필요하면 권장 개선안까지 함께 제시한다.

- 지적된 코드를 직접 읽어 사실관계를 확인한 뒤 판정한다.
- 각 지적사항마다 `판정 / 근거 / 권장 액션` 순서로 정리한다.
- 마지막에 리뷰 전체를 아우르는 **종합 권장 액션** 을 제시한다.
- 직접 수정은 하지 않고 검토 보고서만 작성한다.

## 판정 축

각 지적을 **두 축**으로 판정한다. 한 축으로 뭉치면 "지적이 맞으니 제안대로 고친다"가 되어 땜질 처방이 그대로 통과한다.

- **지적 타당성** — 정확성·실제 영향도·중요도를 따져 **수용 / 일부 수용 / 기각 / 보류**. 문제가 실재하는가.
- **처방 타당성** — **그대로 / 대체안 / 처방 기각**. 원 리뷰가 제안한 수정이 옳은 수정인가.

지적이 「수용」이어도 처방은 「기각」일 수 있다. 맞는 지적에 틀린 처방이 붙는 일은 흔하다. 그 경우 권장 액션에 대체안을 쓴다.

## 권장 액션의 층위

모든 권장 액션에 층위를 붙인다.

| 층위     | 의미                                                               |
| -------- | ------------------------------------------------------------------ |
| 국소     | 해당 라인·블록만 고친다                                            |
| 통합     | 흩어진 같은 처리를 한 곳으로 모은다                                |
| 구조     | 책임 배치·자료구조·호출 관계를 바꾼다                              |
| 되돌리기 | 이전 변경을 걷어내는 것이 정답이다                                 |
| 유예     | 지적은 맞지만 지금 국소로 고치면 더 나빠진다. 조건과 시점을 적는다 |

- 「국소」를 고르면 **왜 국소로 충분한지 한 줄 적는다.** 못 적으면 국소가 아니다.
- **한 파일에 「국소」가 3개 이상 나오면 국소로 두지 않는다.** 통합·구조를 먼저 검토한다.
- 추가를 권하기 전에 **제거·통합·되돌리기를 먼저 검토한다.** 권장안이 전부 "추가"면 그 자체가 신호다.
- 수용·일부 수용 항목을 근본 원인별로 묶는다. **한 원인에 2개 이상 걸리면 개별 패치 대신 그룹 수정안 하나만 낸다.** 항목 수만큼 패치가 나오는 리포트는 항목별로는 맞고 전체로는 틀리다.

## 종합 권장 액션

첫 줄에 **루프 판정**을 셋 중 하나로 명시한다.

| 판정           | 조건                                                                                                    | 지시                                    |
| -------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 적용           | 권장안이 「국소」 소수이고 서로 독립                                                                    | 그대로 적용                             |
| 통합 후 적용   | 근본 원인이 겹치거나 「국소」가 한 곳에 몰림                                                            | 개별 적용 금지. 그룹 수정 하나로        |
| 재설계 후 적용 | 같은 코드가 3라운드 이상 반복 수정 / 이전 라운드가 만든 코드를 다시 지적 / 권장안이 전부 방어 코드 추가 | 땜질을 멈추고 다시 세울 경계를 제시한다 |

판정 근거가 이력에 있으면 `git log -n 10 --oneline -- <파일>` 로 확인한다.

「재설계 후 적용」을 낼 수 있어야 땜질이 끊긴다. 매번 「적용」만 내면 라운드마다 땜질이 한 겹씩 쌓인다.
